# 낚시 사이클 명세 (v1.4.0)

## 목적

`@` → Enter → `낚시` → Enter로 첫 번째 봇을 멘션한다.
내 응답에서 자동어와 일일 한도를 확인하고, 자동어면 `@` → Enter → `수동` → Enter로 해제한다.
통계·기록·미끼 등의 부가 기능은 응답 미확인을 성공으로 처리해서는 안 된다.

## 실행 단계

| 단계 | 성공 조건 | 실패 시 |
|---|---|---|
| 시작 대화 읽기 | 대화 목록 복사 성공, 기준 대화 저장 | 명령을 보내지 않고 정지 |
| 입력 준비 | 대상 창 활성, 보조키 해제, 입력창 포커스 지정. 시작 시 삭제 입력 없이 바로 @ 입력 | 창·보조키가 준비될 때까지 대기 |
| 멘션과 명령 | `@` 입력 완료 → 0.5초 → Enter 1회 → 명령 입력 완료 → 0.5초 → Enter 1회 | 키 입력 API 실패 시 중단 |
| 응답 수집 | 마지막 Enter +0.5초에 1회 검사. 미확인일 때만 +2.5초에 1회 추가 검사 | +3초에 다음 사이클 진행. 추가 대기·반복 복사 없음 |
| 새 명령 확인 | 이전 대화와 겹치는 내용 뒤에 내 새 명령 존재 | 오래된 응답을 사용하지 않음 |
| 자동어 | 내 응답 본문 또는 연결된 별도 자동어 카드 | 다음 명령을 수동으로 변경 |
| 수동 해제 | 수동 전송 후 동일한 최대 2회 검사 | 응답이 없어도 다음 낚시로 진행 |
| 해제 검증 | 다음 낚시 응답 확인 | 3회 해제 뒤에도 자동어면 정지 |
| 완료 판단 | 내 응답의 오늘 횟수/한도, 기존 일일·추가 낚시 종료 규칙 | 불명확한 응답으로 완료 횟수를 늘리지 않음 |

수동 해제는 응답이 없을 수 있다. 다음 낚시가 오면 그 사용자의 미응답 수동 명령을
응답 대기열에서 제외한다. 자동어와 수동 해제는 완료 횟수에 포함하지 않는다.
두 번 모두 새 응답을 확인하지 못하면 다음 낚시 사이클로 진행한다.
확인되지 않은 결과를 성공 횟수나 한도 완료로 처리하지 않는다.
첫 검사에서 응답을 찾으면 두 번째 검사는 생략하고 +3초까지 기다린다.
한도 도달 뒤 기록용 추가 복사도 하지 않는다. 시작 기준 대화 수집과 선택 기능인 미끼 가방 조회는 별도다.

## 복사 순서

### 입력 도중 포커스 이탈과 재개

처음 시작할 때는 입력창의 남은 글 때문에 대기하거나 삭제 키를 입력하지 않고 바로 @부터 진행한다.
Backspace 3회는 입력 도중 포커스를 잃은 후 재개하는 경우에만 적용한다.

`@` 입력부터 마지막 전송 Enter 전까지 채팅방이 전면에서 벗어나면 해당 입력 시도를 중단한다.
채팅방이 다시 전면이 될 때까지 키를 보내지 않는다. 복귀 후 입력창으로 포커스를 옮기고
`Backspace → Backspace → Backspace`를 0.1초 간격으로 입력한 다음
`@ → Enter → 기존 명령 → Enter`를 처음부터 실행한다. 기존 명령이 수동이면 수동으로 재시작한다.
Backspace 입력 도중 다시 포커스를 잃으면 복귀 후 남은 횟수만 입력한다.
재개 준비에서 전체 선택이나 빈 입력창 검사는 하지 않는다.
중단된 입력 시도는 완료 횟수나 자동어 해제 횟수를 올리지 않는다.

마지막 전송 Enter를 이미 보낸 뒤에는 중복 명령을 피하기 위해 처음부터 재전송하지 않고
응답 수집으로 이어진다. 포커스 감지는 준비 확인과 대기 중 주기적으로 수행한다.
OS 포커스 조회와 실제 키 전송 사이의 극히 짧은 전환까지 원자적으로 보장하는 방식은 아니다.

### 정상 복사

명령 입력은 한 작업 스레드에서 순차 실행한다. `@`와 첫 Enter 사이에는
복사·포커스 이동·눌린 키 해제 처리를 넣지 않는다. 키 해제 처리는 `@` 입력 전에 끝낸다.
첫 Enter 전후에 봇 언급 성공 여부를 검사하지 않고 바로 명령을 입력한다.
마지막 Enter 전후에도 입력창의 명령 문자열이나 비어 있는지 여부를 검사하지 않는다.
Enter 입력 후 응답 대기와 대화 선택·복사로 진행한다. 복사한 봇 응답 판별은 유지한다.
Enter 재시도는 하지 않는다.
문자 입력 시간이 길어져도 입력 완료 이후 0.5초 간격을 보장한다.

1. 대상 창·보조키 상태 확인, 기존 텍스트 클립보드 저장.
2. 대화 목록 포커스 → Ctrl+A(누름/뗌을 한 묶음으로 전송).
3. 선택 성공·대상 창·대화 목록 포커스를 다시 확인.
4. Ctrl+C(누름/뗀 키 전체를 한 묶음으로 전송).
5. 대화 목록에 포커스를 다시 연결해 큐를 동기화. 입력창에는 아직 이동하지 않음.
6. 클립보드 시퀀스 변경과 실제 텍스트 준비를 모두 확인.
7. 성공한 경우 입력창으로 복귀하고 기존 텍스트 클립보드 복원.

현재 Ctrl+A는 카카오톡이 제공하는 대화 전체를 선택한다. 정확히 최근 10개만
선택하는 구현은 아니다. 사용자별 응답 연결에 필요한 앞선 명령·횟수를 유지해 해석하며,
직전 복사 이후의 새 명령을 확인한 뒤 최신 내 응답만 실행 제어에 사용한다.
겹치는 대화를 찾지 못하면 소유자를 추정해 낚시를 진행하지 않는다.

## 검증

`python -m unittest discover -q`

복사 순서, 선택 실패 시 복사 금지, 복사 실패 시 입력창 이동 금지, Ctrl 원자적 전송,
미응답 수동 뒤 자동어, 별도 자동어 카드, 다른 사용자 분리, 오래된 자동어 배제,
응답 지연 시 읽기만 재시도, 응답 미확인 시 횟수 미증가를 회귀 테스트한다.
기존 한도·추가 낚시·운영자 이벤트·기록 테스트도 함께 실행한다.

실환경 확인은 카카오톡에서 짧은 낚시 실행, 자동어 출현과 수동 해제,
복사 중 창 전환, 입력창에 `a`/`c`가 남지 않는지 확인하는 순서로 한다.
자동 테스트는 Windows 키 입력과 카카오톡 응답을 대역으로 검사하므로 실제 동작을 보증하지 않는다.
