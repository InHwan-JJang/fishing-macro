# 멘션 입력 진단 (v1.4.0)

목적은 `@`와 첫 Enter 사이에 들어온 키의 종류와 출처를 증거로 확인하는 것이다.
사진만으로는 추가 키의 종류를 식별할 수 없고, 기존 diagnostics.log에는 키 기록이 없다.
입력 순서에 관찰용 진단을 추가한다. 봇 언급 성공 여부는 검사하지 않는다. 과거 사건의 입력을 복원하지는 못한다.

## 수집 범위

- 명령 시작 직전부터 첫 Enter 입력 종료까지, 최대 10초.
- 지정 채팅방이 전면에 있을 때만 키 코드·누름/뗌·시각·주입 여부 기록.
- 키를 문자로 변환하지 않고, 다른 창의 키는 저장하지 않는다.
- Windows 저수준 키보드 훅은 관찰만 하며 키를 생성하거나 차단하지 않는다.
- 실제 키 이벤트와 별도로 프로그램이 요청한 KEY / FOCUS 로그를 기록한다.
- 로그는 실행 파일 옆 `debug/fishing-macro.log`에 저장한다.

## 분석

`MENTION TRACE begin`부터 같은 id의 `MENTION KEY`와 `end`를 비교한다.
`installed=True`인 구간만 훅이 설치된 상태다. 설치 실패 또는 Windows의 훅 제거가
있을 수 있으므로 이벤트가 없다는 이유만으로 외부 입력이 없었다고 단정하지 않는다.

| 항목 | 의미 |
|---|---|
| origin=macro | 이 프로세스가 식별값을 붙여 전송한 키 |
| origin=other-injected | 식별값이 없는 주입 키. 주입한 프로그램 이름까지 알 수는 없음 |
| origin=unmarked | 주입 표시가 없는 키. 하드웨어 입력 등 가능, 출처 확정 불가 |
| vk=231, scan=64 | Unicode @의 VK_PACKET 이벤트 |
| vk=13 | Enter |
| vk=17 또는 162/163 | Ctrl |
| vk=65 / 67 | A / C |
| flags의 0x80 비트 | 키 뗌 |

예상 키는 @ 누름·뗌, Enter 누름·뗌이다. 이 사이의 다른 키가 발견되면
origin과 같은 시각의 KEY 로그를 비교해 프로그램 내부 호출인지 구분한다.
FOCUS 로그는 프로그램 자체 포커스 요청을 나타내며 외부 프로그램의 포커스 변경을 모두 포착하지는 않는다.
카카오톡 내부 메시지 처리나 마우스 이벤트는 이 키보드 진단의 범위 밖이다.

사용 API: https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc
